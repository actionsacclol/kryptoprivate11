## 2. four.meme — the chain's pump.fun

Sources: `four-flap-meme-sdk` (address table, Helper3 usage), the chain.

- `TokenManager2` creates tokens and runs the curves; every trade event comes
  from it. 1,000,000,000 supply, 800,000,000 sold on the curve (`maxOffers`).
- BNB-quoted launches (`quote == 0x0`) graduate at **18 BNB** (`maxFunds`)
  into a PancakeSwap v2 pair (`Helper3.getPancakePair`); then
  `liquidityAdded` is true and the manager refuses trades. Only ~10 % of
  launches are BNB-quoted — the rest are quoted in USDT or tokenised stocks
  (QQQB, …) and are shown, not traded.
- 1 % trading fee (`tradingFeeRate` 100 of 10,000) per fill.
- **Quotes on chain**: `Helper3.tryBuy(token, 0, funds)` → (tokenManager,
  quote, estimatedAmount, estimatedCost, estimatedFee, amountMsgValue,
  amountApproval, amountFunds); `trySell(token, amount)` → (…, funds, fee);
  `getTokenInfo(token)` → (version, tokenManager, quote, lastPrice,
  tradingFeeRate, minTradingFee, launchTime, offers, maxOffers, funds,
  maxFunds, liquidityAdded). No curve formula in the rail.
- **Trades**: `buyTokenAMAP(address token, uint256 funds, uint256 minAmount)`
  payable (selector `0x87f27655`; 403,092 gas simulated with a balance
  override), `sellToken(address,uint256,uint256)` (`0x3e11741f`), and the
  third-party-fee sell `sellToken(uint256 origin, address token, uint256
  amount, uint256 minFunds, uint256 feeRate, address feeRecipient)`
  (`0x06e7b98f`, feeRate in bps of 10,000). Sells pull tokens through
  `transferFrom`, so the manager needs an ERC-20 approval first.
- **Events** (topics read from the chain): TokenCreate
  `0x396d5e90…cad20` = `TokenCreate(address creator, address token, uint256
  requestId, string name, string symbol, uint256 totalSupply, uint256
  launchTime, uint256 launchFee)`; TokenPurchase `0x7db52723…62942` and
  TokenSale `0x0a5575b3…bae19` = `(address token, address account, uint256
  price, uint256 amount, uint256 cost, uint256 fee, uint256 offers, uint256
  funds)`, no indexed params. Two more topics (`0x48063b12…`, `0x741ffc46…`,
  one zero word) are not decoded. `LiquidityAdded`'s signature is not
  published; graduation is detected through `getTokenInfo.liquidityAdded`.
- Measured 2026-09-09: **135 TokenCreate in 800 blocks (~6 min)** — about 20
  a minute.

## 3. Rail design for BNB

- Venue resolution (`venue.ts`): Helper3 record → `fourmeme-curve`
  (BNB-quoted, not graduated) or `pancake-v2` (graduated: the helper's pair,
  else the v2 factory's); no record → v2 pair vs WBNB → `pancake-v2`; else a
  v3 pool vs WBNB (tiers 1 %, 0.25 %, 0.05 %, 0.01 %) → `pancake-v3`; else
  `unknown` (Flap, GraFun, USDT-quoted pairs are shown, not traded).
- Execution: curve buy direct (fee follows as its own transfer — no BNB curve
  router yet); curve sell through the platform's native fee parameter (the
  whole 0.5 % to the treasury; no referrer split on this venue); pool trades
  through Universal Router 2 with the fee inside and the buy-side interlock.
- Discover: index of TokenCreate (first fill 13k blocks ≈ 1.7 h, rolling
  44k ≈ 5.5 h), curve state by Helper3 `getTokenInfo` multicall, Graduating
  from TokenPurchase/TokenSale logs of the last 700 blocks, Migrated from the
  index's launches whose helper says `liquidityAdded`, Trending from
  GeckoTerminal `bsc`.
- Gas rule `gasPrice`; receipt timeout 60 s; public-endpoint gate 8 rps.

## 4. Not built

Own tape (BSC has no sequencer feed; a WebSocket `eth_subscribe(logs)` on the
manager would do), a BNB curve router for atomic buy fees, USDT-quoted and
stock-quoted four.meme launches, Flap and GraFun, PancakeSwap Infinity pools.


## Corrections from the 2026-09-09 audit (read this before trusting §2/§3)

- `Helper3.getPancakePair` returns a PancakeSwap **v3** pool, not a v2 pair (its
  `factory()` is the v3 factory). Graduated tokens are routed by quoting both
  venues, not by that address.
- A **v2 pair address existing means nothing about liquidity** on BSC: pairs live
  forever once created and are usually abandoned when the real market is v3.
- four.meme's `sellToken` only accepts amounts that are whole multiples of 1e9
  (`GW` otherwise), so every percentage sell must be floored.
- Many four.meme tokens charge a **creator buy tax** (1/2/3/10 % seen) that
  `tryBuy` does not model; quotes must come from a simulation.
- The public endpoint refuses `eth_getTransactionReceipt` at every depth and
  historical balances past ~50 blocks. `CHAINS.bnb.receiptRpc` names a second
  endpoint for both.
- Only ~15 % of launches are BNB-quoted, and the log range publicnode actually
  enforces is a ~10,000-block reach plus a result cap, not the 5,000-block range
  stated in §1.
