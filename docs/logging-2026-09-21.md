# Logging and the support bundle (2026-09-21)

User: "hows our logging, we should probably have extensive logging for all
features n whatnot. in settings exporting logs too so users can send, and we
have logs for all, paper, live, scripts, launching, scout, copy trading etc."

Audited every feature, then filled the holes and built the export.

## 1. What the audit found

The logger itself was already good: `electron/system/logger.ts` writes
`<userData>/logs/app.log`, 5 MB with one rotated `app.log.1`, buffered and
flushed off the hot path, `flushSync` before quit, disk failures swallowed,
and **every line redacted before it reaches either the in-memory feed or the
disk**. 275 call sites across the app; the engine alone has 106.

Well covered already: manual trading verdicts, paper fills, copy trading (14
sites, the best-covered subsystem), user scripts, advanced orders, the EVM
rails, chat bots, crashes (their own dated files), MCP lifecycle.

**Silent, and each one a layer everything else sits on:**

| module | lines | logged |
|---|---|---|
| `electron/chain/rpcClient.ts` | 1,386 | fallback + rejected keys only; a park with no fallback was invisible |
| `electron/data/http.ts` | 1,239 | **nothing** |
| `electron/engine/walletScout.ts` | 700 | **nothing** |
| `electron/engine/scoutScan.ts` | 180 | **nothing** |
| `electron/engine/walletHistory.ts` | 196 | **nothing** |
| `electron/engine/mcpTools.ts` | 415 | **nothing** |

So a user reporting "the Scout scan hung" or "there are no prices" handed
support an empty file, on jobs that run for minutes and spend hundreds of
calls. And there was **no export anywhere** — `About` showed the folder path
and told the user to find `app.log` themselves.

## 2. What was added

**The Scout, which had none at all.** `scoutScan.ts` and `walletHistory.ts`
take an injected log sink (so they stay offline-testable) and now report:

```
scout scan solana: reading the last 6h (3,848 wallet(s) already on record)
scout scan solana: pump.fun trade history: rate limited, retrying in 34s
scout scan solana: done in 128s — 60/60 unit(s), 4,102 trade(s) read, 1,233 recorded,
  2,869 already known, 71 call(s), +412 wallet(s)
wallet read Whae11…: done — 200/200 read, 41 swap(s), 12 new, 29 known, 0 unreadable, 21 call(s)
```

**The provider layer.** `http.ts` logs a park once, when it is new or longer
than the one already running — so a backlog firing into an existing park
cannot fill the log with one sentence, which is the exact shape the 2026-09-06
storm had. Already firing on this machine:

```
provider pumpfun (frontend-api-v3.pump.fun) rate limited — paused 20s
  (it asked for 1). Prices and charts from it are stale until then.
provider birdeye: allowance spent — paused for 360 min. Top up the plan or
  switch it off in Settings.
```

**The RPC layer.** `noteRateLimit` logs a park, throttled to one line per key
per minute. `noteFallback` already covered the rescued case; this covers the
one it could not — a park with no fallback configured, where the call just
waits and the user sees a spinner with nothing behind it.

**The AI connection, which could spend money with no audit trail.** Every tool
call is logged with its arguments and how long it took, and — added after a
live test showed the gap — every refusal, logged inside the server where the
gate actually refuses:

```
AI called get_token mint=So1111…1112 → ok in 1687ms
AI tried buy_token → REFUSED: This connection is read only. Trading tools are
  switched off in the app under Settings → AI connection.
```

Arguments are safe to log because of the design in `shared/mcp.ts`: a tool
argument is an intent, never a key, a fee or an endpoint.

**Settings changes.** Only rejections were logged; an accepted patch was
silent. Support's most common question is "what is different between the run
that worked and the one that did not", so accepted changes now log field by
field, with anything key-shaped reduced to `<changed>`:

```
settings changed: execution{liveSlippagePct=18, maxLiveSol=0.5} · rpc{heliusApiKey=<changed>}
```

**Wallet lifecycle.** `select`, `remove`, `setHome` and withdrawals were
already logged; `generate`, `import` and `rename` were not — a gap exactly
where "where did my wallet go" lands. Public keys and labels only; never the
secret, and never even its length.

## 3. The support bundle

`electron/system/diagnostics.ts` + Settings → **Logs**. One button, one file.

Nothing is sent anywhere. The app has no telemetry and this does not change
that: it writes a file where the user chooses, or fills the clipboard. There
is no "phone home" and there will not be one.

In it: versions and platform; the settings with every secret **removed**;
what is switched on right now (live or paper, the scanner, copy configs and
scripts with their modes, wallets per chain, the AI connection, the bots);
the provider board with parks and last errors; a file inventory by name and
size only; crash filenames; then `app.log.1` and `app.log`.

Not in it: no private key, no seed, no API key, no balances, no holdings, no
trade history. The header says all of that in plain words, and states the one
honest caveat — the log names coins the user looked at and trades they made,
the same things the app shows on screen.

Size: capped at 6 MB so it can be attached (Discord's free limit is 8 MB). On
this machine the real bundle is 5.6 MB. Over the cap it cuts from the FRONT
and says so, because the end of a log is the part that explains what happened.
The button shows the size before writing, since a 6 MB attachment is a
different decision from a 40 KB one.

### The leak it caught

Testing the redaction against a **real profile** rather than a fixture found a
genuine hole. The first rule matched `apikey`, `token`, `secret` and friends —
and `anthropicKey` walked straight through it. So would `heliusKey`,
`birdeyeKey`, or whatever the next provider is called.

The fix inverts the rule: **a name ending in "key" is a secret**, unless it is
`publicKey` or `pubkey`, which are addresses and are themselves a diagnosis.
An allowlist of known secret names is a list someone has to remember to add
to, and nobody does.

Verified after the fix against the real `settings.json`: all five real secrets
removed (`token`, `heliusApiKey`, `birdeyeApiKey`, `giphyApiKey`,
`anthropicKey`), with `commitment: "processed"` and `liveEnabled: true` still
there — the file is still a diagnosis. The real `app.log` and `app.log.1`
(5.2 MB together) were scanned for the same five strings and contain none of
them, so the logger's own redaction holds on live data.

That case is now pinned in `test/diagnostics.test.mjs` with the provider-key
shapes that would have leaked.

## 4. What is still thin

Not done, in rough order of value:

- **`liveSigner.ts`** logs nothing of its own (1,072 lines). The engine logs
  the verdict; the route, quote, slippage inputs, tip and per-stage timing are
  not on disk. A "my trade filled at a terrible price" report has the outcome
  and not the inputs.
- **Scanner rejections.** Why a candidate failed a filter is never logged, so
  "it ignored an obvious runner" is undebuggable.
- **Script `info`/`warn` from inside the sandbox** stay in an in-memory ring
  and never reach `app.log` — a user's own breadcrumbs are lost. Only `error`
  is forwarded.
- **`launcher.ts` / `pumpLaunch.ts`** log nothing: no metadata upload, no IPFS
  step, no dev-buy amount. A launch that fails before the signer leaves no
  line.
- **`paperBook.ts`** uses `console.warn`, which never reaches the file, so
  "my paper positions vanished" has no on-disk trace.
- **Wallet Lab** logs fund and collect totals but not per-wallet outcomes.
- `walletSwap.ts` (the copy-trade buy-side decode) is silent.

## 5. Rules to keep

- Redaction happens **before** the in-memory feed, not just before disk. The
  Console page reads `recent`, so a key must never be stored raw either way.
- A new module that runs for more than a second, or spends provider calls,
  logs a start and a finish with counts. The Scout is the cautionary tale.
- Anything that can refuse a user's intent logs the refusal with the reason.
  A silent refusal is the hardest class of bug to report.
- Throttle by key, not globally. A storm must not become a storm of logging.
- Never add a secret name to an allowlist. Match the SHAPE and allowlist the
  few things that are public.
