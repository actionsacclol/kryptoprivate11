# Navigation speed — 2026-09-08

The ask: "make navigating the important panels as fast as possible". Measured
first, then changed, then measured again with the same driver
(`npm run test:nav:e2e`, below). Everything here is uncommitted on
`release/beta.7` with the rest of 1.1.0.

## What was slow, and why

The driver clicks each sidebar entry in a running dev app and reads, inside
the renderer, when the panel's heading appears ("shell") and when it goes quiet
(400 ms without DOM mutations, no spinner, no "Loading…" text — "ready").
Baseline, cold → warm visit, milliseconds:

| Panel     | shell (before) | ready (before) | shell (after) | ready (after) |
|-----------|---------------:|---------------:|--------------:|--------------:|
| Portfolio |   51 / 4       | 6 880 / 5 315  |   24 / 17     |   453 / 432   |
| Trades    |  179 / 6       | 4 289 /   706  |   32 / 23     |   490 / 479   |
| Watchlist |   38 / 6       | 2 163 /   912  |   31 / 22     | 1 536 / 2 290 |
| Token     | 1 046 / 597    | 4 909 / 4 239  |   10 /  7     | 4 942 / 4 636 |
| Discover  |  150 / 124     |   735 /   711  |   10 / 10     |   417 / 448   |
| Wallet    |  187 / 4       |   990 /   785  |   24 / 13     |   583 / 653   |
| Orders    |   64 / 4       |   483 /   420  |   28 / 22     |   444 / 439   |

"ready" includes the 400 ms quiet window, so 430–490 means the page was done
30–90 ms after the click. The two rows that still read high are honest:
Watchlist paints its last rows at once and the background refresh lands
1–2 s later (that is the stale-while-revalidate working); the Token page
paints in 10 ms and its chart still waits on the provider walk (see the chart
section — bounded now, and gone entirely for pump curve tokens).

Where the seconds went (measured, not guessed):

1. **Every page remounted from nothing.** `App.tsx` keys the route div, so
   Portfolio/Trades/Watchlist started empty and asked main to rebuild what they
   had shown a moment earlier.
2. **The portfolio build priced everything.** Closed positions and every
   ledger mint went through the provider queue on every summary, with
   unpriceable mints (curve tokens with no route) re-asked each time.
3. **"Nothing" was never cached.** A GeckoTerminal "no pool" or "no candles"
   answer was re-fetched on each poll, on a 2.1 s-gap host that parks on 429.
4. **Discover's ~10,000 elements** were rebuilt on every return, then all four
   columns fetched cold.
5. **Lazy chunks loaded on click**, with the fade animation spent on the
   spinner; the two three.js scenes created a WebGL context synchronously in
   the same frame as the page's first paint.

## What changed

### Data path (main + renderer)

- **The engine keeps its last portfolio build** (`lastPortfolio`) and pushes
  every rebuild as an EngineEvent `portfolio`. `portfolio:summary { stale: true }`
  returns the kept copy at once (marked `stale` past 3 s or after a fill,
  which also starts the rebuild); without the flag it still awaits a real
  build. Fills and paper fills call `markPortfolioDirty()` — one trailing
  rebuild per burst, so a five-wallet fan-out does not start five builds.
- **Holdings likewise** (`lastHoldings`, EngineEvent `holdings` on change,
  `wallet:holdings` answers from the kept read and refreshes past 2 s).
  Both token programs are read in parallel.
- **The build itself is cheap**: holdings first, then pending-fill
  reconciliation; only OPEN positions are priced (`summaryMany(open)`),
  closed-only mints get a name from whatever is already cached (summary
  cache, ledger symbol, paper book) and an unpriced, detached name lookup
  capped at 40, skipping mints marked unpriceable.
- **Negative caches**: `market:nopx:<mint>` (5 min, written when a summary
  has no price), `gt:pools:none:<mint>` (45 s), `gt:ohlcv:none:<pool>:<iv>`
  (30 s). The token page's own chart asks with `priority: true`.
- **Renderer route cache** (`src/state/routeCache.ts`): the last portfolio,
  holdings and token rows a page painted. Pages seed from it on the first
  frame, show an age stamp / "updating…" while stale, and subscribe to the
  engine's pushes so every open page updates together. Cleared on
  `walletSwitched`. Pinned by `test/routecache.test.mjs`.

### Perception (renderer)

- **Navigation is a `useTransition`**: the page being left stays on screen
  until the next one can render — a route whose chunk is still loading no
  longer swaps the pane for a spinner. The sidebar highlights the target at
  once; a hairline under the top bar shows a pending transition. Opening a
  token is NOT a transition (entry-bundle page, ~80 ms of render, and a
  transition let Discover's poll updates restart it — 400+ ms measured).
- **Chunk prefetch** (`src/routeLoaders.ts`, the one place page chunks are
  named): sidebar hover/focus warms the chunk; the eight most-visited routes
  are warmed one at a time in idle time 2.5 s after first paint.
- **Discover is never unmounted.** Off-route it is `content-visibility: hidden`
  (rendering state kept, nothing painted or hit-tested, `aria-hidden`), stops
  its column polls (`active` prop), and re-reads wallet/live/settings when it
  returns. Return visit: 150 ms → 10 ms, no cold column fetch.
- **three.js on its own chunk** (Wallet's tome, the Observatory's orb are
  `lazy` behind the effects switch), and the WebGL context is created two
  frames after mount so the page's text paints first and a visit that leaves
  immediately never pays for a context it will not show. The orb replays the
  launches it recorded while waiting so the first frame is not empty.
- **Ink fade** 0.3 s → 0.12 s, started inside the Suspense boundary (when the
  page can paint, not when its chunk starts loading); off under
  `prefers-reduced-motion`.
- **Provider status identity**: `TerminalProvider` keeps the same
  `providers` array when a poll returns identical data, so consumers do not
  re-render for nothing.

### Chart fast path (`market.candlesFast`)

- The on-curve skip that shipped in the data batch never fired: a pump
  token's `poolAddress` IS its bonding curve before migration, so the
  `!poolAddress` clause was always false. Fixed to `launchpad === 'pumpfun'
  && bondingCurvePct < 100`; GeckoTerminal is skipped for those (it has no
  such pool), Birdeye (keyed) still runs. Curve tokens: 7.5–8.7 s → 0.4–1.1 s.
- When the fast path holds nothing at all (no cache, no tape), it now gives
  the full load **1.2 s**; past that the page gets an honest pending
  placeholder (`source: 'none'`, "Loading history…") and the real series —
  empty or not — is pushed as the `candles` event when the walk lands, so the
  spinner always ends in either candles or the true note. One push per load
  however many fast answers were handed out. A failed walk after a
  placeholder pushes a "Chart load failed" note rather than leaving the
  spinner.

## Rules that must hold

- **No trade path reads a stale copy.** Sell-all, recovery, scripts and the
  portfolio build call `engine.holdings()` fresh; `portfolio:summary` without
  `stale` awaits a rebuild; nothing on a trade path consults `market:nopx:`.
  The kept copies exist for what is on screen, not for what is signed.
- **Wallet switch drops everything wallet-scoped** — `clearWalletCaches()` in
  main (kept build, kept holdings, in-flight shares) and `walletSwitched` in
  the renderer cache. Token rows survive: a price is the same for everyone.
- **A stale copy says so.** `stale`/`generatedAt` on the summary, an age stamp
  or "updating…" on the page. Never a fresh-looking number from an old build.
- **The reduce-effects guarantee is unchanged**: with the setting unknown or
  on, no WebGL context is created (the lazy scene is never even fetched).
- **Discover hidden is still Discover**: its `active` prop gates polls and the
  wallet re-read; anything added to it that runs on a timer or listens to the
  document must check `active`.

## How to re-measure

```
KRYPT_DEBUG_PORT=9333 npm run dev        # accept the onboarding gate once
npm run test:nav:e2e -- out.json         # PORT=… overrides the debug port
```

The driver is read-only (it clicks the sidebar and one token card) and prints
one line per route for a cold and a warm pass, plus IPC probe timings before
and after. It needs a wallet with some history to say anything about
Portfolio/Trades. Observatory reports no heading (its title is not an `h1`)
in both baseline and after — a driver artefact, not a regression.

## Not done / watch

- Trades' "ready" is dominated by the 400 ms quiet window now; the closed
  list itself arrives in the background rebuild (title shows "updating…").
- The Token page's chart still waits on GeckoTerminal for migrated tokens
  when the host is parked (4–6 s); the page, price and position paint first.
- The full `npm test` suite and the type check pass; the live app was
  exercised through the driver (two passes) and the CDP candle probe, not by
  hand.
