# BNB Smart Chain rail audit — 2026-09-09 (after the Robinhood audit the same day)

The user asked for a swarm over BNB: "make sure all bnb works". Five auditors in
parallel — the four.meme money path, PancakeSwap routing, market data and PnL,
the renderer/settings/parity surface, and a live read-only probe against BSC —
each told to first check that the morning's Robinhood fixes actually hold on the
shared code as BNB uses it. Every finding then went to a skeptic told to refute
it, with the P1s re-proved independently on chain.

Read-only throughout: `eth_call`, `eth_estimateGas` with state overrides,
`eth_simulateV1` with transfer traces, `eth_getLogs`. The live prober's harness
hard-refused `eth_sendRawTransaction`; across thirteen runs it was never
attempted.

**Result.** Five P1s, ten P2s and a long P3 tail. All fixed and verified. Two
findings were refuted and several downgraded.

---

## The five P1s

### 1. A near-empty pair was chosen over the real pool, and the trade filled

`resolveBnb` took a PancakeSwap v2 pair if the factory returned any non-zero
address. It never read its reserves and never compared it against v3. On BSC a
v2 pair contract lives forever once created, so a token whose real market is a
v3 pool usually also has an abandoned one. The quote came from the same dead
pair the swap used, so the minimum agreed with the terrible fill and nothing
reverted.

Measured on four tokens the auditor and the skeptic each picked independently: a
0.1 BNB buy of one returned 0.025 tokens where the v3 pool returned 172.73 — a
6,792× loss, status success. Others were 945×, 1,252× and 25,689×.

**Fixed.** The venue is now chosen by what it actually quotes: both venues are
probed and the better one wins, and neither is accepted without a live quote.
Verified after the fix: CAKE moved to v3, which pays 0.29 % more.

### 2. Four.meme tokens quoted in USD1 were offered as tradeable once graduated

The guard that refuses a non-BNB-quoted launch ran *after* the graduation
branch, so it only ever covered live curves. About 85 % of four.meme launches
are quoted in USD1, USDT or a tokenised stock; each became buyable the moment it
graduated. Three were confirmed resolving with no refusal at all.

**Fixed.** The quote guard now runs first, exactly as Robinhood's does, and the
refusal names the actual asset.

### 3. No BNB trade could ever confirm or gain a cost basis

The default BNB endpoint refuses `eth_getTransactionReceipt` outright — "Archive
requests require a personal token" — even for a transaction in the head block,
and refuses historical balances more than about fifty blocks back. So every BNB
trade timed out unconfirmed, every fill ended unreconciled, and every position
showed no entry price, no cost and no profit or loss, permanently.

I confirmed it myself: the head-block receipt is refused while the same endpoint
serves the transaction, and a second BSC endpoint returns the receipt fine.

**Fixed.** The chain config now names a receipt endpoint, used for receipts and
for the balances that price a fill. A refusal is recognised rather than retried
for a minute, and when historical balances are unavailable the fill is priced
from the transaction itself with a note saying so.

### 4. The app simulated one transaction and signed another

The four.meme buy simulation hard-coded a minimum of zero, so it could never see
a slippage failure, and the quote was marked "simulated" even when the
simulation had failed. Meanwhile the platform's own estimator ignores a
**per-token creator buy tax** — measured at 1 %, 2 %, 3 % and 10 % tiers — so the
real fill can be up to 9.8 % below the quote. At the shipped 5 % slippage the
skeptic measured **18 of 38 fresh-curve buys reverting**, with control
re-simulations at the same block proving it was not price movement.

**Fixed.** The simulation now runs the exact minimum that will be signed, and
the quote comes from the simulated fill rather than the estimator, so the
minimum is derived from reality. The tax is disclosed on the quote. Verified
after the fix: eight of eight fresh curves plan at the default slippage, with
taxes of 1.0 % to 8.9 % named.

### 5. Partial sells were broken on every four.meme token

Four.meme's contract only accepts sell amounts that are whole multiples of a
billion base units and reverts otherwise. Percentage sells almost never land on
that boundary, so **24 of 28 measured partial sells reverted** — 25 % and 75 %
failed in every single case, while 100 % always worked. The user paid for a
token approval first and only then discovered it.

**Fixed.** Four.meme sell amounts are floored to the contract's unit, and the
sell is now simulated before the approval is broadcast. Verified on a live
holder: 10, 25, 50, 75 and 100 % all plan and simulate.

## P2s fixed

- **Migrated was structurally empty.** It was built from the launch index, which
  reaches about an hour, while a curve needs 18 BNB to graduate. Zero graduates
  among 1,448 indexed launches. It is now seeded from PancakeSwap's live pool
  listings and priced from the pool, so the rows carry real market caps instead
  of the identical frozen numbers every graduate would otherwise show.
- **New served about a dozen rows whatever you asked for**, because the
  BNB-quoted filter ran after the candidate list was cut to eighty. The pool is
  now proportional to the request.
- **The graduating column collapsed silently** when its single oversized log
  query failed, falling back to newborn launches and still reporting success.
  The scan is chunked and capped like its Robinhood twin, and a degraded scan
  now says so.
- **The sold-out window** between a curve selling out and its pool being created
  was offered as tradeable while every buy and sell reverted. It is now named.
- **A fabricated deployer** of all zeros was shown on every four.meme token page,
  reading as "renounced". It is now the indexed creator or an em dash.
- **The shared platform contract was listed as each token's own pool**, so every
  four.meme page showed the same address.
- **Curve fees were billed on the requested amount**, not the filled one, on
  buys the curve clamps and refunds. Rebased from the receipt.
- **The sell floor was about 1.5 % looser than the number on screen**, because
  the contract compares against the gross while the app derived it from the net.
- **A disabled chain still polled and still served market data.**
- **The wallet handlers answered for Robinhood whatever chain asked.**

## P3s fixed

Revert strings are decoded into sentences, including four.meme's two-letter
codes, and no longer print ETH amounts on the BNB rail. The sell path drops a
referrer that is the trader or the treasury, as the buy path already did. The
reported sell fee accounts for the router taking its two cuts in sequence. An
unreachable custom endpoint is detected and falls back to the public one instead
of leaving the chain dark under a green label. A provider's zero market cap
falls through to fully diluted value. Gas and fees show as unknown rather than
zero when nothing could be reconciled. Plus the renderer set: the settings card
no longer tells BNB users to add a key it does not offer, pasted addresses show
which chain they will open on, the trade panel shows a total-out line and
confirms unusually large buys, the Discover hints say the columns are
BNB-quoted only, and the filter bar has chips for the BNB and Robinhood pools.

## Refuted

The spot price does not lag the platform's quoter by 14 % (measured 0.06–0.2 %
across eight curves, which is the platform fee). The chart fallback for a fresh
graduate is not a one-line gate — four.meme's curve is a shared contract, not a
pool id, so it needs a different source. Two renderer claims were wrong on the
code.

## Left open

Position value on EVM is still spot times amount rather than a sell quote. The
BNB launch index still reaches only about an hour on the free endpoint, so the
New and Graduating columns cover that window; a user's own endpoint does not yet
widen it. Trending rows on BNB carry no native price. There is still no EVM loss
breaker, balance cap, withdraw button or Trades-page row — all labelled as
Solana-only rather than silently missing.
