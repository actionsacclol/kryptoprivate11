# EVM rail audit — Robinhood Chain (and the shared BNB rail), 2026-09-09

The user asked for an audit swarm over the new Robinhood chain: "make sure all
functions just like the solana chain functions and everything works perfectly
and try to catch bugs or any potential issues".

**Method.** Eight auditors in parallel, one lens each — execution path, keys and
signer policy, fees and anti-tamper, market data and PnL, renderer parity,
settings/lifecycle/rate limits, a live read-only probe against the chain, and a
Solana-versus-Robinhood feature matrix. Every finding then went to a skeptic
told to refute it, with instructions to re-prove the P1s independently on chain.
Read-only throughout: nothing was signed or broadcast, and no wallet file was
touched (probes used `eth_call`, `eth_estimateGas` with state overrides,
`eth_simulateV1` and `eth_getLogs`).

**Result.** 60 findings raised, 51 survived verification, 4 refuted, the rest
downgraded. Two P1s, both real, both fixed and pinned. The same recipe as
`beta-audit-2026-08-28` and `release-audit-2026-09-03`.

---

## The two P1s

### 1. A Pons curve position could not be sold at all

`electron/evm/trade.ts` built a curve sell as a bare `sell(tokensIn, minOut,
recipient)` with no approvals. The curve PULLS the tokens with `transferFrom`,
so every sell from a wallet that had not already approved the curve reverted
`ERC20InsufficientAllowance` — in Paper and in Live. The quote then fell back to
the documented formula, and the user saw only "Simulation failed: execution
reverted". A position bought through Krypt on the chain's primary venue could
not be exited through Krypt.

Proved twice on chain, on different curves: the app's own `encodeSell` calldata
from a real holder reverted `0xfb8f41b2` with the curve as spender and an
allowance of 0; the same call with a slot-1 allowance state override succeeded
(92,226 gas). Real sellers on chain show `Approval(seller→curve)` before every
`CurveSell`.

**Fixed** in `plan()`'s pons-curve sell branch, mirroring the four.meme branch
that already did it right: read the allowance, and when it is short, queue a
`token→curve` approval carrying its own policy with `approveSpenders` pinned to
that curve. `simulateSell` takes an optional allowance override
(`erc20.allowanceStateOverride`) so the quote is the curve's own answer instead
of the formula while the approval is still pending.

**Pinned** by a new block in `test/evmrail.live.mjs` (`npm run test:evm`): it
finds a live curve holder and asserts the plan carries exactly one approval,
pinned to that curve, with a simulated quote. Verified against an unapproved
holder (1 approval, 0.000645 ETH quoted) and an approved one (0 approvals).

### 2. A wallet could exist only in memory

`electron/evm/evmWallet.ts persist()` assigned the in-memory cache BEFORE
writing the file. If the write or rename failed (AV lock, disk full, the
2026-09-03 failure class), the exception escaped an IPC handler that had no
`try/catch`, the renderer's busy flag never cleared, and the next list showed a
wallet whose key existed only in RAM — auto-active, shown in the top bar, ready
to be funded and gone on restart. Solana's `wallet.ts` writes first and assigns
last, exactly to prevent this.

**Fixed**: `cache = next` moved after `renameSync`, `persist` throws while a
load failure is set (as Solana does), the five wallet IPC handlers catch and
return a failure, and the renderer wraps generate/import in `try/finally`.

## P2s fixed

| Finding | What was wrong | Fix |
|---|---|---|
| Stock- and USDG-paired Pons launches | About half of all Pons launches are quoted in USDG or a tokenised stock. The resolver routed them as tradable and the Migrated column priced the pool's other currency as if it were ETH: one NVDA-paired token showed a market cap of $816k against DexScreener's $39k, 20× over. | `resolveRobinhood` refuses any launch whose `pairToken` is not native (shown, never traded); Discover lists only native-paired graduations; the summary fallback nulls price/mcap/liquidity otherwise. |
| Uniswap v3 was dead both ways | Robinhood's Universal Router takes an extra per-hop price field. Every v3 buy and sell the rail built reverted `SliceOutOfBounds()`. The quote came from QuoterV2 and succeeded, so the panel showed a price and the trade died at simulate. | The v3 swap input gets a sixth `uint256[]` field (empty) on Robinhood only; BNB keeps PancakeSwap's stock five. Verified on chain: 167,247 gas plain, 203,980 with the fee leg, where both previously reverted. |
| A referrer could block every exit | The referrer leg is inside the router call. A referrer address that cannot receive native currency (a token contract, Permit2) reverted the whole swap, so a bad referrer in Settings made pool positions unsellable. A fee must never block a trade. | The referrer is probed once (`estimateGas` of a 1 wei transfer) and dropped to the treasury when it cannot receive; results cached per address. |
| The Alchemy key reached the logs | viem puts the full URL in every transport error, and the key sits in the URL path. Those messages went to `app.log`, the in-app Console page and error toasts. | `redactSecrets` scrubs URL-path keys and `push()` redacts before storing; the rail logs `shortError` (never the raw message); the crash file is redacted too. |
| The ledger overwrote itself | An `evm-fills.json` that existed but could not be read was treated as "no file", and the next write replaced every cost basis. Solana's ledger had the same shape. | Both ledgers now separate "absent" (fresh) from "unreadable" (keep a failure, refuse to write, log). |
| A landed fill could vanish | Between `sendRawTransaction` and the receipt the fill existed only in a local variable, for up to 45–60 s. A crash or quit in that window lost it entirely — the token would not even appear as a holding, since holdings come from the ledger's known tokens. | The hash is computed from the signed bytes before the send; the fill is recorded pending the moment it is broadcast (`recordFill` is now idempotent on hash); `before-quit` awaits a bounded `evmRail.drain(8s)` and flushes both ledgers. A lost send reply ("already known") is followed by hash instead of reported as failed. |
| The bots lied about arming | `/status` read only the Solana engine, so a phone check said "Live trading: disarmed" while Robinhood was live. | `/status` lists each enabled EVM chain's Paper/Live state. |
| The legal documents omitted the chains | The privacy document enumerates every host the app contacts; no EVM host was listed. The terms said the fee is always charged inside the same transaction, which is untrue for curve venues. | Both amended, `TERMS_VERSION` bumped so existing users re-accept, and the host list is pinned by `test/legal.test.mjs`. |
| The UI said "no wallet" when it meant "still asking" | `rail.state()` awaited the head block and the USD price before answering. Under a rate-limit park that took 8–23 s, and every EVM surface renders a null state as "no wallet / Paper" — including a refusal to arm. | State returns the local facts at once and races the two network reads against a short budget, falling back to the last known values; the renderer now distinguishes loading from absent. |
| A bad RPC key looked like an outage | No 401/403 handling: a wrong or revoked key made Discover, token pages and trades fail with "HTTP request failed" and no fallback. | The endpoint is marked rejected for 15 minutes and the rail falls back to the public one; `EvmState.rpcStatus` says so in Settings. A Cloudflare bot challenge (Robinhood's public endpoint answers a hot IP with a 403 HTML page) is parked and retried, not mistaken for a bad key. |
| BNB's index could die for the session | The catch-up scan asked for every block since the last look. publicnode refuses logs older than ~10,000 blocks, so after about 75 minutes on another chain the scan threw forever and the BNB columns stayed dead until restart. | Past a window behind, the index refills from scratch instead of catching up. |
| BNB's Graduating column was structurally empty | The activity lookback was 700 blocks (~5 minutes). four.meme launches ~20 a minute and almost all die at 0 %, so the column only ever saw newborns; climbers are older than the launch index reaches. Measured: 0 rows while 9 tokens were above 3 %, the top at 66.75 %. | The lookback is the whole reachable range, and a token trading right now is a candidate even when its launch predates the index (its age then renders as an em dash, per the honest-null rule). Verified 0 → 9 rows. |

## P3s fixed

Custom revert errors are decoded into sentences ("Slippage: the curve would pay
X, the floor was Y") instead of "execution reverted". The sell quote is taken at
the same 15 % floor the sell actually executes at, so the panel no longer labels
a tighter minimum than the transaction carries. Curve fees are rebased on what
the curve actually took, from the receipt, so a buy that crosses the graduation
line is not billed on the refunded part. A broadcast trade with no receipt yet
is a new `pending` stage and a warning, not an error. `tokenDeltaFromReceipt`
survives a Transfer log with an indexed value. The signer refuses to sign for a
wallet other than the one the plan was made for, and receives the real chain id.
A transfer policy entry accepts exactly `0x`. Realised PnL is unknown, not
negative, when more tokens were sold than this install bought. A sell's fee row
no longer inflates the average entry price. Discover's Migrated liquidity is
tagged as a graduation-time figure. The chart falls back to the launch curve's
history when a fresh pool has none, and says when GeckoTerminal is rate-limited
rather than "no history yet". A market cap of 0 from a provider falls through to
FDV. The startup "file could not be read" dialog covers the EVM wallet file. A
chain switched off in Settings takes no orders and does no polling. The kill
switch disarms every chain. Renderer: a stale arm bit can no longer mislabel a
quick buy, the watchlist banner no longer prints "ok", the disarm reason is
shown, small balances no longer render as zero, and the Solana-only features
(hotkeys, name search, Trades, export, breakers, caps, withdraw) say so.

## Refuted

The factory record's `sweptQuote`/`sweptTokens`/`sweptAt` reading zero is not an
ABI mis-order — the factory simply clears them once the pool exists, and the
pool key does not depend on them. The chat bots cannot be made to trade a 0x
address (the mint regex rejects it before any handler). Two renderer formatting
concerns were wrong on the code.

## Left open, by decision

- **Position value is spot × amount, not a sell quote** (Solana uses a sell
  quote). Labelled honestly in the panel; a thin curve therefore flatters a
  position. The pieces to fix it exist (`simulateSell`, the quoters).
- **The renderer bundle carries the treasury constants.** Editing that copy
  redirects nothing (main resolves through the integrity blob), but the recipe
  is readable. Same on Solana; the fix is a renderer-safe shared module.
- **A curve fee is still dropped** when the receipt arrives after the timeout,
  or the app quits between fill and fee. Revenue only; no user loss, and the
  Krypt curve router removes the case for buys once deployed.
- **No EVM loss breakers, caps, withdraw, Trades-page rows or hotkeys.** All now
  labelled as Solana-only rather than silently missing.
